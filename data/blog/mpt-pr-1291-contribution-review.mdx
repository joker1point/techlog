## 一、项目概述

为开源项目 MoneyPrinterTurbo（119k+ star、18k+ fork 的 AI 短视频生成器）新增 **OpenAI 兼容文生图素材源（`openai_image`）**：通过任意 OpenAI 兼容 `/v1/images/generations` 端点（本地 ComfyUI/SD 网关或云端中转），按脚本关键词逐张生成图片并渲染为带放大效果的视频片段。

### 7. 最有价值的一课：维护者在 #1296 上的深化（commit `428dd4e`）

- **我们的缺陷**：修复时 `except Exception` 一把抓——解码失败和落盘失败都走"跳过关键词"。若失败原因是本地环境（磁盘满/权限），循环会为每个关键词继续付费生成→落盘失败→再付费，**所有付费图片全部丢失**
- **维护者的修复**：新建 `_OpenAIImageDecodeError` 只归入解码失败（远端的错→跳过合理）；`image.save` 刻意留在保护区外（本地的错→异常上抛，任务立即止损）
- **通用教训（付费 API 容错设计的第二层分类学）**：
  - 第一层（#1291 review 学到）：按**确认状态**分类重试——未确认不重试防重复扣费
  - 第二层（#1296 深化学到）：按**错误归属方**分类降级——远端的错跳过继续，本地的错立即止损
  - `except Exception` 是粒度不足的反面教材：测试能过，但语义边界模糊，付费场景下就是"烧钱循环"和"止损"的区别
- 面试可讲：被维护者指出的不是 bug 而是设计粒度，说明这类系统的错误处理需要"失败语义建模"思维

### 8. 事实修正：计费安全先例的归属（防止面试翻车）

- **"未确认不重发"不是我们的原创**：WaveSpeed 源的贡献者 ichengzeyi 在 `9a739da`（2026-08-21，早我们十天）已用 `WaveSpeedUnconfirmedTaskError` 完整实现，且选择最保守的"abort 整个任务"
- **我们的真实增量**（被 review 指出后做的差异化，非照抄）：
  - 按连接阶段细分超时：ConnectTimeout（确定未送达）可安全重试，读超时（未确认）不重试——WaveSpeed 不做此区分
  - 降级粒度：跳过关键词继续 vs WaveSpeed 的 abort 全任务。计费论证：不同关键词是独立计费任务，跳过不构成重复扣费
- **我们的教训**：v1 漏复用了同文件里现成的模式（只学了 WaveSpeed 的按需生成流程，漏了提交策略）——**读参考实现要学到错误处理语义层，不是只抄流程**
- **一个我们比先例松的点**：提交 5xx 我们退避重试、WaveSpeed 视为未确认 abort（维护者未 flag，属可辩论边界）
- **面试正确姿势**：讲"知道先例、漏过先例、被指出后消化并做出有理由的偏离"，不讲"首次系统化"（代码可查证，夸大会翻车）

## 三、踩坑记录与解决方案

### 1. Streamlit text_area 必须 Ctrl+Enter 提交

- **现象**：WebUI 填完"视频关键词"点击生成，任务失败在"生成关键词"阶段——关键词输入框值为空，系统转而调用 LLM 生成，撞上额度问题
- **根因**：Streamlit 的 `st.text_area` 输入后需 **Ctrl+Enter** 提交（普通 Enter 只是换行），页面上的 "Press Ctrl+Enter to apply" 是唯一提示
- **解决**：浏览器测试工具用 `submit: true`（Enter）无效，改 `press_key("Control+Enter")` 成功
- **教训**：自动化测试 WebUI 表单时，凡 text_area 都要显式 Ctrl+Enter；用户侧文档/占位符文案最好提示这一点

### 2. GITHUB_TOKEN 环境变量劫持 gh 认证

- **现象**：`gh auth login` 走不下去，提示 "The value of the GITHUB_TOKEN environment variable is being used for authentication"
- **根因**：环境变量里残留一个**失效的** GITHUB_TOKEN，gh 优先级是环境变量 > keyring 存储
- **解决**：

```
Remove-Item Env:\GITHUB_TOKEN -ErrorAction SilentlyContinue
[Environment]::SetEnvironmentVariable("GITHUB_TOKEN", $null, "User")
[Environment]::SetEnvironmentVariable("GITHUB_TOKEN", $null, "Machine")
gh auth login   # 之后 gh auth setup-git 配置 git 凭证
```

- **教训**：gh 排障第一步永远是 `gh auth status` + 检查 `$env:GITHUB_TOKEN`

### 3. Agnes 文生图端点间歇性 503（队列满）

- **现象**：同一天可用性约 60~70%，请求随机返回 503 queue full
- **应对**：这反而成为宝贵的测试素材——真实覆盖了 503 退避重试后恢复、重试耗尽跳过关键词后任务仍正常出片两条降级路径
- **教训**：不稳定上游不是测试的敌人，是降级路径的免费验收；已在模型调用表.md 标注该端点状态

### 4. 千问兼容端点免费额度耗尽

- **现象**：403 `AllocationQuota.FreeTierOnly`，"仅免费模式"开关下无法再生成文案/关键词
- **教训**：长开发日要预留额度或提前关掉免费模式限制；直接手填文案+关键词可绕过（CLI 的 `--video-script` + `--video-terms`）

### 5. Windows 下 Python 嵌套引号命令

- **现象**：RunCommand 执行 `python -c "..."` 内含引号的临时脚本反复语法错误
- **解决**：改为写临时 .py 文件执行，或用 PowerShell 的单引号包裹 + `''` 转义
- **教训**：复杂 Python 代码一律落盘为文件，不要塞 `-c`

### 6. Edit 工具字符串匹配失败（行尾空白）

- **现象**：`Edit` 报 "String to replace not found"，明明代码看起来一样
- **根因**：目标文件行尾有不可见空白差异
- **解决**：拆成更小的替换单元；先 Read 精确区域再复制原文
- **教训**：Edit 前先 Read 目标行，绝不凭记忆构造 old_string

### 7. 测试用 TemporaryDirectory 的作用域陷阱

- **现象**：3 个单测失败——断言文件存在时文件已消失
- **根因**：`with TemporaryDirectory()` 块结束后目录被删除，而断言写在了 with 块外（或 mock 的回调延迟到块外才落盘）
- **解决**：改用 `tempfile.mkdtemp()` + `self.addCleanup(shutil.rmtree, ...)`
- **教训**：测试夹具的生命周期要覆盖全部断言点

### 8. 测试隔离：本地 config.toml 泄漏进单测

- **现象**：新增 prompt_template 用例后，其他用例在开发者本机跑失败、CI 跑过
- **根因**：`config.app` 是动态 dict，本地 config.toml 里配了 `openai_image_prompt_template`，污染了"默认行为"用例
- **解决**：setUp 显式 `config.app.pop("openai_image_prompt_template", None)`（后同加 `openai_image_size`）
- **教训**：项目配置是全局可变的，每个用例都要在 setUp 里清洗相关键

### 9. 首次贡献者 fork PR 的 CI 不自动跑

- **现象**：`gh pr checks` 显示 no checks reported
- **根因**：GitHub 默认策略，fork PR 的 workflow 需维护者点 "Approve and run"
- **应对**：不慌，这不是失败；本地已跑过等价命令（pytest + ruff），CI 只是复验
