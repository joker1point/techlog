有些项目从一个需求开始，这一个从一次好奇开始。

我手机上装着一款体积只有 3.1 MB 的应用，界面该有的都有。某天我决定把它拆开，想知道这么小的安装包里究竟装了什么。

## 好奇心：拆开一个 3.1 MB 的 App

过程比预想的顺利。解包、反编译、确认它用什么写的——很快看清了底牌：它是把 Web 前端装进原生外壳的做法，业务代码根本不在安装包里。顺着它的默认配置，我又把它运行时才去下载的三十个代码分块全部拉下来读完。最后确认了一件挺反直觉的事：

**这个应用自己几乎不干活。** 界面、交互、业务逻辑全在远程托管的网页里；那 3.1 MB 绝大部分是「把网页搬进手机」的那层壳，外加一堆前端框架的运行时。

这段经历留给我的不是「怎么照抄」，而是一个更朴素的问题：

> 如果我只是想给自己的博客开一个直达入口，为什么要扛这么大一整个架子？

<Callout type="key" title="我真正需要的其实只有一个 WebView">
安卓系统早就自带了一个完整的浏览器内核（WebView）。它不需要额外依赖、不需要联网初始化、不占安装体积。我想做的事——打开直达、能返回、断网有提示——全都能在它之上补齐。多出来的每一层框架，都是我要额外背负的成本。
</Callout>

于是「TechLog 薄壳」这个项目就诞生了。目标定得很死：**零第三方依赖、只用系统 WebView、安装包控制在几十 KB 量级。**

## 先想清楚：一个壳究竟要补哪几件事

听起来「打开一个网址」是最简单的事，但真要做得像样，得回答几个问题：

- **同源链接要留在壳里**。点一篇文章如果被甩到系统浏览器，用户会瞬间出戏——那是「跳出去」，不是「用应用」。
- **外域链接要交给系统浏览器**。反过来，博客里指向外站的链接不该被关在这个小窗口里，那是对用户的劫持。
- **返回键要走网页历史**。用户按一次返回，应该是「回到上一篇/上一页」，而不是「啪」一下整个应用退掉。
- **没网时要有个说法**。网页加载失败默认是白屏，对着白屏发呆和看到一个「轻触重试」的提示，体验差得很远。

这四件事，就是整个壳的全部复杂度来源。

## 写壳：一个 Activity 加一个 WebView

实现落在一个 Java 文件里，核心就是一个 WebView 加两段逻辑。

第一段是**导航分流**，落在 `shouldOverrideUrlLoading` 里：如果目标地址是 https 且域名属于博客，就放行让 WebView 自己处理；否则抛给系统去打开。

```java
public boolean shouldOverrideUrlLoading(WebView view, WebResourceRequest request) {
    Uri uri = request.getUrl();
    if ("https".equalsIgnoreCase(uri.getScheme())
            && SITE_HOST.equalsIgnoreCase(uri.getHost())) {
        return false;          // 同源：留在壳内
    }
    startActivity(new Intent(Intent.ACTION_VIEW, uri));  // 外域：交给系统
    return true;
}
```

第二段是**返回键**，落在 `onBackPressed` 里——有网页历史就后退，没有才退出应用：

```java
public void onBackPressed() {
    if (webView.canGoBack()) {
        webView.goBack();
    } else {
        super.onBackPressed();
    }
}
```

再加上 `onReceivedError` 里判断「是不是主文档加载失败」，是就把一个本地的兜底文案盖上去，点一下重新加载。最后用 `saveState` / `restoreState` 保住旋转屏幕时的页面状态。整套逻辑到此结束，没有一行多余的代码。

配置侧我刻意保持极简：权限只要一个 `INTERNET`，图标全部用矢量图（不塞任何 PNG 素材），最低支持到 Android 7.0。

## 装到手机上：图标为什么不见了

第一次装完，我发现了两个「图标找不到」的问题，一个是我自己犯蠢，一个是真 bug。

**第一个是概念错位。** 从浏览器点「下载」，文件只是进到了「下载」目录，那叫下载，不叫安装。用户需要在文件管理器里再点一次、确认「允许未知来源」，它才会真正装到桌面。这是安卓的安全设计，不是应用的问题——但它足以让第一次接触的人一脸懵。

**第二个是真 bug。** 我满怀期待地装完、打开、一切正常，可以在桌面上却死活找不到它的图标，只能从别处把应用「启动」出来。查下去发现根因藏在清单文件的一行常量里：

```xml
<!-- 写错的版本：把 category 误写成了 action -->
<category android:name="android.intent.action.LAUNCHER" />
```

我把 `category` 的名字误写成了 `android.intent.action.LAUNCHER`——听起来差不多，但系统只认 `android.intent.category.LAUNCHER`。这一个单词的差别，让包管理器**从未注册过任何桌面入口**：应用能装、能跑、能从命令启动，就是不在桌面上留痕。

改掉这一行、把版本推到 1.0.1，图标立刻正常。

<Callout type="learn" title="这类 bug 为什么难被发现">
它不报错、不崩溃，构建全绿、安装成功、启动正常——所有「机器能验证的环节」都通过了。唯独用户第一眼要看的那个图标，是缺的。**「程序跑起来了」和「功能对用户可见」，从来不是一回事。**
</Callout>

## 模拟器实测：把「能编译」变成「真的能跑」

打包成功不等于能用。为了真正确认这四件事都成立了，我开了一个安卓模拟器，把 APK 真装进去跑了一遍——也因此踩了一堆以前没遇到过的坑。

返回键也验证通过：在文章页按一次返回，回到首页；在首页再按一次，才退出到桌面。分毫不差。

但让「模拟器能连上网」这件事，花掉的时间比写壳还多。

### 坑一：模拟器的网络被宿主机的代理「拦死」

现象很直接：模拟器里连 `ping` 一个公网地址都百分之百丢包，DNS 解析报未知主机，应用里的 WebView 直接抛 `ERR_NAME_NOT_RESOLVED`。表面看像模拟器「没网」。

根因在我自己的机器上：我平时用一类代理软件上网，它**只监听本机的回环地址**。而模拟器是通过 NAT 出网的，它的流量压根不经过宿主机的回环——于是模拟器自以为在联网，实际上所有请求都被丢掉了。

解法不是去改模拟器启动参数（我试过，那个 `-http-proxy` 选项**对 WebView 用的浏览器内核不生效**），而是直接在安卓系统里设一个全局代理，把它指向宿主机的回环：

```bash
adb shell settings put global http_proxy 宿主机别名:代理端口
```

这个「宿主机别名」是安卓模拟器内网里一个保留地址——从模拟器看过去，它就代表那台跑着代理软件的物理机。设完之后，博客首页在 WebView 里完整渲染了。

### 坑二、三：模拟器会「凭空消失」，系统界面会卡死

调试过程中模拟器还崩过好几次，每次都是**进程无声无息地没了，日志里找不到一句报错**。查下来是两件事叠加：

一是**渲染模式选错了**。我一开始指定了 `angle_indirect`，但这个版本的模拟器已经不认它，于是静默回退到「用宿主显卡直通」——在宿主机内存本就紧张的情况下，这条路最容易把图形进程拖垮。换成纯软件渲染 `swiftshader_indirect` 之后稳定多了。

二是**内存**。我一开始用的是带应用商店的重型系统镜像，加上模拟器本身要吃两三个 GB，宿主机一紧张，系统的界面进程就报「无响应」。对策很土但有效：把模拟器的内存和 CPU 核数调小，遇到弹窗先点「等待」而不是「关闭」——点关闭反而会把界面进程杀掉，整台模拟器跟着一起走。

这三个坑的共同点值得单拎出来说：**它们全都不报错。** 模拟器消失时没有堆栈，渲染回退时没有警告，界面卡死时应用日志干干净净。如果只盯着「应用日志」，你会把「环境的问题」误判成「代码的问题」。真正的线索在别处——模拟器自己的启动输出、宿主机的可用内存、以及那个「无响应」弹窗。

真机上不会有这一组坑。这是我为「用模拟器代替真机」付的学费。

## 这趟折腾留下的几句话

回看整件事，最大的收获不在代码，而在几个判断：

**「别人那么做」和「你需要那么做」是两回事。** 拆开那个 3.1 MB 的应用，我学到的不是怎么模仿它的架构，而是反过来看清：那么多层，对「我」这个场景，根本可以不要。

**交付物的每一层都要按它真实的形态验收。** 构建通过、安装成功、进程存活，全都不能替代「用户在桌面上看得到图标」「按钮的文字他看得清」「点击下载真的有反应」。

**当所有报错都消失时，先怀疑环境。** 模拟器那三个坑一个堆栈都没有，逼着我把目光从应用日志移向宿主机与运行时本身。

一个 14 KB 的壳，装的是一整座博客。而把这些多余的东西一层层剥掉之后，剩下的那点复杂度，恰好就是我想亲手写清楚的部分。
