## 如何快速接手一个项目并构建深度项目认知

接手一个陌生项目，最忌讳的就是一上来扎进某个函数里。我总结了一套四阶段方法论，配合 agent 技能栈，可以快速建立深度认知。

---

## 阶段一：宏观定向（1-2 小时）

目标：搞清楚项目是什么、给谁用、依赖什么。

1. **读项目自述**：README、docs、`package.json`/`requirements.txt` —— 项目是什么、给谁用、依赖什么
2. **看目录结构**：分层方式暴露架构风格（MVC / 分层 / 模块化），找出核心域目录
3. **找入口文件**：`main`/`app`/`index`，追启动流程，看系统初始化了什么
4. **读配置**：环境变量和配置项 = 系统能力清单 + 外部依赖清单

---

## 阶段二：架构建模（半天）

目标：建立系统的心智模型。

5. **画架构图**：模块关系 + 数据流向（你刚装的 archify 就是干这个的）
6. **抓数据模型**：数据库 schema / 核心类型定义——**数据结构比代码逻辑稳定得多，是认知锚点**
7. **追一条主链路**：选最核心的用户场景，从入口到输出完整走一遍代码，其他链路都是变体

---

## 阶段三：运行验证（半天）

目标：用实践固化认知。

8. **跑起来**：跑不通的项目建立不了真实认知
9. **改点东西**：修个小 bug 或加个小功能——实践是认知固化最快的方式，**读十遍不如改一遍**

---

## 阶段四：持续深化

目标：在长期迭代中加深理解。

10. **读测试**：测试是最好的使用文档，还告诉你边界条件
11. **读 git log**：演进史 + 热点文件 = 系统的痛点所在
12. **沉淀笔记**：建立个人 wiki（你的 qmd / llm-wiki 技能适用）

---

## 关键原则

- **先全局后细节**：避免一上来扎进某个函数
- **读代码产生假设，用运行时行为验证假设**
- **能画出来、讲出来才算真懂**：输出倒逼输入

---

## 技能栈覆盖

我现在的技能栈正好覆盖全流程：

```
zoom-out 宏观视角 → archify 画架构图 → SearchCodebase 语义检索 → qmd 沉淀
```

这套流程的核心价值在于：把"接手陌生项目"从一件靠悟性的事，变成了一件有章可循、可复用的工程动作。
