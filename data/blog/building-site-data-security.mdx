### 我建站如何确保数据安全

作为一个独立开发者，我搭建站点时把数据安全放在架构最底层。我的核心选型是 **Cloudflare 隧道 + 国内服务器**：Cloudflare 的全球网络提供 CDN 加速、DDoS 防护和 WAF，无需开放公网端口即可暴露服务，天然隐藏源站 IP；配合国内服务器保证访问速度，形成"安全在前、速度在后"的架构。

#### 开发阶段把好第一关

代码层面，我坚持"修改即补单元测试"。浏览器点击只能覆盖主流程，单测才能守住边界条件和异常分支。同时跑一遍 SAST 静态扫描（如 Semgrep），提前揪出 SQL 注入、硬编码密钥等低级缺陷。每次提交前用自动化接口做回归测试，确保新代码没有破坏旧功能。

#### API 是防护重点

我把 API 安全拆解成六个维度：

**参数校验** — 对类型、长度、格式做白名单限制，严防 SQL 注入和 XSS。

**权限控制** — 校验资源归属防横向越权（IDOR），按角色隔离防纵向越权，Token 设置合理有效期和刷新机制。

**稳定性** — 写操作加幂等性设计（业务流水号），引入熔断和限流，防止下游故障拖垮全站。

**错误处理** — 统一返回脱敏提示，绝不向客户端暴露堆栈或 SQL 语句。

**审计日志** — 记录操作人、IP、接口和结果，但日志本身也做脱敏，避免泄露密码或 Token。

**传输与存储** — 强制 HTTPS + HSTS，密码哈希存储，响应体按需裁剪敏感字段。

#### 测试与渗透验证

除浏览器测试外，我用 Postman 覆盖正常用例、边界值、非法参数和异常数据。人为制造下游超时和网络闪断，验证熔断和兜底逻辑。按预估 QPS 压测，寻找瓶颈并校准限流配置。

渗透测试聚焦 OWASP API Security Top 10，重点排查失效的对象授权、过度数据暴露、资源缺乏限流等问题。遍历资源 ID、替换 Token 测试水平与垂直越权，用自动化工具辅助但坚持手工验证。同时关注业务逻辑漏洞，如金额篡改、优惠券重复使用、条件竞争等。

#### 发布与线上不掉链子

上线采用灰度发布，让少量用户先验证，观察错误率和延迟。对业务异常、状态码和响应时间设置监控告警。最关键的是验证一键回滚能力，确保数据兼容，出问题时能分钟级恢复。

#### 二阶安全补足短板

**接口安全** — 短信验证码前置图形验证码或滑块，加 IP 频率限制防短信轰炸；敏感接口必须 JWT 鉴权，按用户 ID 做行级数据隔离。

**内容安全** — UGC 文本和图片先审后发，敏感词过滤加图片检测，前端渲染避免 `dangerouslySetInnerHTML`，后端做标签过滤。

**文件上传** — 不走本地磁盘，直接进 OSS 并开启防盗链，限制图片类型和 MIME 校验，禁止可执行文件上传，存储路径随机重命名。

**第三方调用** — 调用 OpenAI 等第三方 API 时，密钥仅存服务端环境变量，用户输入做长度截断和过滤，防止 Prompt Injection 和 Token 耗尽攻击。

---

安全不是一次性任务，而是贯穿开发、测试、发布、运维的持续性工程。把每一层做扎实，才能让用户数据真正安心。
