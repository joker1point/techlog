## 一、RAG 与检索：把「找资料」这件事做扎实

这是最完整的一条线，也是首页「**专题 · VDB-News**」专区的主体：从一个自我维护向量库的 AI 情报平台出发，从整体架构、分块层重构，到检索实验、选型框架与事件聚类。**建议按顺序读**——每一篇都是下一篇的铺垫。

- [RAG 链路全解析：从文档入库到混合记忆的实战架构](/blog/rag-pipeline-architecture) —— 先建立坐标系：文档入库、向量化、召回重排、Prompt 拼接，以及基于 Node.js + ChromaDB + SQLite 的三层混合记忆方案。

- [把 143 块拆到 45 块：一次 RAG 分块重构，和它揭出来的评测陷阱](/blog/rag-chunking-refactor-and-eval-traps) —— 分块层的完整重构（全库 1959 → 1120 块、HTML 残留 38.3% → 0%），以及改好之后「怎么证明它变好了」——三个评测自身的陷阱。

- [修 5 坏 2，还是修 3 坏 0？——一次 55 题的多路召回实验](/blog/multi-route-retrieval-experiment) —— 给检索补一条字面路（BM25）修专名盲区：全开能多答对 5 题但弄坏 2 题，改成条件触发则多答对 3 题、零回退。含 λ 的两次扫描与一条「不算数的修复」的诚实标注。

- [RAG 还必要吗：从 130 条技术评论里提炼出的选型决策框架](/blog/rag-vs-agent-retrieval-decision-framework) —— 什么时候该上 RAG、什么时候该交给 Agent 自主检索：按更新频率、查询频率、数据规模、领域特性做决策。

- [什么才算「同一件事」：热点聚类的三轮试错，与把判同交给模型之后发生的事](/blog/what-counts-as-same-event) —— 管道里最难的聚类环节实录：纯余弦与实体词两轮失败、标题近乎重复的保守上线、模型判同的评测（0.850→1.000），以及一个反直觉前提——聚类的「料」由信源结构决定。

## 二、Agent 工程：架构、治理与防御

把 Agent 当成一个需要工程化治理的系统来看：先定位它该不该存在，再谈架构怎么演进、Skill 怎么治理、失败怎么兜底、注入怎么防。

- [Workflow vs Agent：用 7 维度框架定位你的项目](/blog/workflow-vs-agent-7-dimensions) —— 动工之前先回答「这里到底需不需要 Agent」；能说清「为什么不需要」和硬说「这里有 Agent」一样重要。

- [我的 Agent 架构演进：Skill 压平 Sub Agent，Restatement 又把它拉了回来](/blog/agent-architecture-evolution-skill-restatement) —— 一条完整的踩坑迭代链：三层架构 → Skill 压平降 Token → 长任务撞上步骤合并跳过、规则失效 → Restatement 机制与 Sub Agent 回归。

- [我是如何保证 Agent Skill 多而不乱的？](/blog/agent-skill-governance) —— 700+ Skill 库的四层治理体系：选得对、管得住、改不坏、不腐烂。

- [Agent 健壮性设计：工具调用与模型调用失败的容错与兜底](/blog/agent-fault-tolerance-design) —— 错误分类 → 退避重试 → 熔断 → 按能力等级优雅降级；以及「API 成功但业务失败」这类潜在错误的识别。

- [Agent 怎么防止 Prompt 注入：四层纵深防御体系](/blog/agent-prompt-injection-defense) —— 输入侧、模型侧、执行侧、输出侧四层防御，其中执行侧权限管控是最硬的底线。

- [如何沉淀 Agent 每次的踩坑经验](/blog/agent-lessons-precipitation) —— 把「记住教训」从模型自觉变成基础设施：规则强制捕获 → 定期蒸馏 → 协议化进化。

- [把 22 篇项目文档蒸馏成一个可进化的全局技能](/blog/dev-lessons-skill-distillation) —— 上一套方法论的落地实例：按领域分文件、经验带场景标签与溯源，并内置进化协议。
